## 1. Executive summary

The service is in good technical shape for an internal or single-tenant deployment. Network egress is guarded well,
failures are explicit, and the test suites (118 unit tests, 12 real-Chrome tests, a 140-case live parameter test)
pass. The overall weighted score is **72/100**. The top three risks are:

1. **Insecure defaults.** Without a `.env`, the API binds to all interfaces and accepts unauthenticated requests
   (A01).
2. **Unbounded request bodies.** Bodies are read in full before authentication, so exposure without a reverse
   proxy is a memory-exhaustion risk (A02).
3. **Pickled result cache.** The cache uses pickle serialization (CVE-2025-69872) on a directory whose permissions
   are not enforced (A03).

**Most important action:** make the defaults safe. Bind to loopback unless configured, refuse a non-loopback
bind without `API_KEY`, and cap request bodies in the application.

## 2. Overview

- **Purpose:** an HTTP-first FastAPI service that turns web pages and documents into Markdown. It uses HTTPX,
  Trafilatura and MarkItDown, falls back to Selenium/Chrome for JavaScript pages, can anonymize output with Presidio,
  and caches results in diskcache (SQLite). A Google Colab notebook runs it with one browser slot behind a

- **Stack:** Python ≥ 3.11, FastAPI/Starlette/Uvicorn, HTTPX (HTTP/2), Selenium 4, Trafilatura 2.2, MarkItDown 0.1,

## 4. Verdict

**Conditional.** The code is production-ready for a single-tenant deployment that meets all of these conditions:

- `HOST` is a loopback address, or `API_KEY` is set.
- The service runs behind the nginx example (or an equivalent) with HTTPS enabled and `client_max_body_size`
  enforced (A01, A02, A13).
- `RESULT_CACHE_DIR` is a private directory owned by the service user (A03).
- `LOG_JSON` stays `false` until A04 is fixed.

Direct public exposure (for example via a tunnel without a reverse proxy) should wait for A01 and A02. The Colab
notebook already sets `HOST=127.0.0.1` and requires `API_KEY`, but its tunnel path has no body size limit of its
own.

## 5. Top issues (ranked by business impact)

```
[HIGH] Security — A01: open binding and optional authentication by default
  File:     app/config.py, app/main.py
  Lines:    config.py 22, 26; main.py 51–55 (check_auth)
  Problem:  HOST defaults to 0.0.0.0 and API_KEY to None. check_auth skips every check when no key is set,
            and nothing warns about this combination at startup.
  Why:      A plain `pip install -e . && python run.py` (no .env, or an environment without it, such as a
            container) exposes an unauthenticated extraction service with Chrome on every interface.
  Impact:   Anyone who can reach the host can use it as a crawling/rendering proxy and exhaust CPU with browser
            jobs. SSRF protection still applies, but abuse, cost and IP-reputation risks remain.
  Fix:      Default HOST to 127.0.0.1. Refuse to start (or at least log an error) when HOST is not loopback
            and API_KEY is empty.
  Example:  host: str = os.getenv("HOST", "127.0.0.1")
            ...
            if not self.api_key and self.host not in {"127.0.0.1", "::1", "localhost"}:
                raise ValueError("Set API_KEY before binding to a non-loopback HOST")
```

```
[MEDIUM] Security/API — A02: request bodies are read in full before authentication
  File:     app/main.py (routes); FastAPI routing
  Lines:    main.py 86–91; fastapi/routing.py reads the body at 433–446 before solve_dependencies at 481
  Problem:  /crawl and /crawl/batch take JSON bodies. FastAPI reads and parses the whole body before the
            Security(check_auth) dependency runs, and neither Starlette nor Uvicorn limits body size.
  Why:      Unauthenticated clients can make the process buffer and parse arbitrarily large bodies.
  Impact:   Memory and CPU exhaustion when the service is reachable without nginx (client_max_body_size 2M) —
            for example through the Colab tunnel.
  Fix:      Add a small ASGI middleware that rejects Content-Length and streamed bodies above ~1 MB with 413
            before routing; keep nginx's limit as a second layer.
```

```
[MEDIUM] Storage/Security — A03: pickle-serialized cache on a directory with unenforced permissions
  File:     app/resources.py
  Lines:    35–50 (_open_stores)
  Problem:  diskcache.Cache uses pickle by default (CVE-2025-69872, no fixed release). mkdir(mode=0o700)
            only applies when the directory is created; an existing RESULT_CACHE_DIR keeps its permissions.
  Why:      Anyone with write access to the cache directory can execute code in the service when it reads
            cached results, rate reservations or metrics.
  Impact:   Local privilege escalation on shared hosts or shared volumes.
  Fix:      Store JSON values, and verify directory ownership and mode at startup (POSIX).
  Example:  self.cache = diskcache.Cache(path, disk=diskcache.JSONDisk, size_limit=...)
            info = base.stat()
            if os.name == "posix" and (info.st_uid != os.getuid() or info.st_mode & 0o077):
                raise RuntimeError("RESULT_CACHE_DIR must be private to the service user")
            (cache values: result.model_dump(mode="json"))
```

```
[MEDIUM] Security — A04: the JSON log sink keeps loguru's diagnose=True
  File:     app/logging_setup.py
  Lines:    52–59 (JSON sink); compare 61–74
  Problem:  The human-readable sink sets diagnose=False. The JSON sink sets neither diagnose nor backtrace,
            and loguru defaults both to True (loguru/_defaults.py 43–44).
  Why:      Exception traces then contain local variable values, which can include request options (proxy
            credentials), page text or tokens.
  Impact:   Sensitive data in the log aggregation pipeline — the setting most likely used in production.
  Fix:      Pass diagnose=False, backtrace=False to the JSON sink as well.
```

```
[MEDIUM] Operations — A05: failed crawls are not logged server-side
  File:     app/main.py, app/service.py
  Lines:    main.py 57–59 (crawl_error_handler), 111–113 (batch except); service.py 34–38
  Problem:  Only unexpected exceptions are logged (as type names). CrawlErrors (502 navigation failures,
            504 deadlines, 503 queue/PII) and extraction failures inside 200 responses leave no trace.
  Why:      Operators only see Uvicorn access lines with status codes.
  Impact:   Intermittent failures — such as the reported Colab errors — cannot be diagnosed from logs.
  Fix:      Log one structured line per failed URL: status, sanitized message, mode, host (no path or query),
            elapsed time, extraction_status.
```

```
[MEDIUM] API — A06: clients can disable or raise the operator's per-domain rate limit
  File:     app/schemas.py, app/rate_limiter.py
  Lines:    schemas.py 40, 93; rate_limiter.py 18–20
  Problem:  crawl_rate_limit_rps accepts 0–100, and the server default only applies when the field is
            omitted. A rate of 0 disables the per-domain limit (`if rate > 0`).
  Why:      DEFAULT_DOMAIN_RATE_LIMIT_RPS cannot act as a politeness ceiling. Only the global limit is
            enforceable.
  Impact:   A single client can hammer one host from the operator's IP.
  Fix:      Treat a positive server default as the maximum.
  Example:  default = config.default_domain_rate_limit_rps
            if default > 0:
                requested = values["crawl_rate_limit_rps"]
                values["crawl_rate_limit_rps"] = default if not requested else min(requested, default)
```

```
[MEDIUM] Dependencies — A07: no lockfile; every install resolves fresh versions
  File:     requirements.txt, pyproject.toml, .github/workflows/ci.yml
  Lines:    requirements.txt 1–2; pyproject.toml 20–32; ci.yml 19, 38
  Problem:  Dependencies are open ranges, requirements.txt is `-e .`, and CI installs whatever resolves that
            day. No hashes, and no vulnerability scan in CI.
  Why:      Builds are not reproducible, and a compromised or broken release can enter production unnoticed.
  Impact:   Surprise breakages (for example a Trafilatura or Selenium minor release) and supply-chain exposure.
  Fix:      Generate a hashed lock (uv or pip-tools) for runtime + documents and install from it in CI and
            production. Add a `pip-audit -r requirements.lock` step and automated update PRs.
```

```
[MEDIUM] Testing — A08: the public links feature has no behavioural tests
  File:     app/utils.py; tests/test_api.py
  Lines:    utils.py 157–265 (_is_internal, _classify_link, extract_links_detailed_from_html);
            test_api.py 104, 211
  Problem:  Tests only assert that links are suppressed for anonymized responses. Categories, internal

  Why:      The code runs only inside conversion workers, so in-process coverage also shows 0 % for utils.py.
  Impact:   Regressions in a response field clients rely on go unnoticed.
  Fix:      Add unit tests calling extract_links_detailed_from_html directly (categories, www/internal,

```

```
[MEDIUM] Performance — A09: HTML is parsed up to three times per document
  File:     app/worker_tasks.py, app/preflight.py, app/service.py
  Lines:    worker_tasks.py 12–24; preflight.py 32; service.py 90–93
  Problem:  The document is parsed three times: prepare_html in convert_html, again in needs_browser, and a
            third time for links. needs_browser runs for every mode although its result is only used in auto.
  Why:      BeautifulSoup/lxml parsing dominates CPU for large pages (up to max_bytes = 10 MiB).
  Impact:   Wasted CPU on Colab's single conversion worker, and longer queues for batches.
  Fix:      Compute the routing decision only for mode=auto and reuse one parsed tree.
  Example:  use_browser = options.mode == "auto" and needs_browser(fetched, converted)
```

### Security
- 🟠 **A01**: open binding and optional authentication by default. See top issues.
- 🟡 **A02**: request bodies read before authentication, without a size limit. See top issues.
- 🟡 **A04**: `diagnose=True` in the JSON log sink. See top issues.

```
[LOW] Security — A12: interactive docs and OpenAPI schema are public when API_KEY is set
  File:     app/main.py
  Lines:    48
  Problem:  FastAPI() keeps the default /docs, /redoc and /openapi.json routes without authentication.
  Why:      The full request surface (proxy option, insecure TLS option, limits) is advertised to anyone.
  Impact:   Easier reconnaissance of a key-protected deployment.
  Fix:      Disable the routes when an API key is configured, or guard them with the same dependency.
  Example:  FastAPI(..., docs_url=None if config.api_key else "/docs",
                   redoc_url=None, openapi_url=None if config.api_key else "/openapi.json")
```

```
[LOW] Security (local) — A14: loopback egress guards accept any local client
  File:     app/egress_proxy.py
  Lines:    100–102 (start_server on 127.0.0.1); 45–49 (upstream Proxy-Authorization)
  Problem:  Guards listen on a random loopback port without authentication. Per-job guards add the caller's
            upstream proxy credentials to every tunnel.
  Why:      On a shared multi-user host, another local process can use a live guard as a proxy, including
            the caller's authenticated upstream proxy.
  Impact:   Local misuse of proxy credentials. Not relevant on single-tenant hosts or containers.
  Fix:      Document single-tenant use, or run workers in a separate network namespace/user.
            (Chrome's --proxy-server cannot carry credentials, so a token check needs another channel.)
```

### Logic & correctness

```
[LOW] Correctness — A16: raw deflate response bodies are rejected
  File:     app/body_reader.py
  Lines:    15
  Problem:  "deflate" uses zlib.decompressobj(15), which requires the zlib wrapper. Some servers send raw
            deflate (wbits −15), which HTTPX's own decoder accepts.
  Why:      Such responses fail with "Invalid compressed HTTP response".
  Impact:   Rare fetch failures on old or misconfigured servers.
  Fix:      Retry the first chunk with zlib.decompressobj(-15) when the zlib header check fails.
```

```
[LOW] Correctness/Maintainability — A17: the batch failure reason mirrors the service's success rule
  File:     app/main.py, app/service.py
  Lines:    main.py 28–37; service.py 111–119
  Problem:  _failure_reason re-derives why success is false from public fields. A new success condition in
            the service would fall through to "Extraction incomplete".
  Why:      Two places must change together.
  Impact:   Misleading batch error text after future changes (none today).
  Fix:      Compute the reason next to `success` in CrawlService and pass it to the batch endpoint internally,
            or cover every success condition with a test.
```

## General observations (no single source location)

- **Positive:**
  - Egress is guarded consistently for HTTPX and Chrome: DNS validation, pinned numeric dialing, redirect
    revalidation, and subrequests forced through the guard.
  - Anonymization fails closed.
  - Tokens are compared in constant time.
  - Deadlines cover queueing, fetching and conversion.
  - Worker processes are terminated with their children on timeout.
- **Measured:** unit tests cover 81 % of `app/` statements in-process. Code that runs only in spawned workers
  (`worker_tasks.py`, parts of `utils.py`, `converter.py`, `js_fetcher.py`) is under-reported; its real coverage
  comes from the worker and Chrome tests.
- **Needs verification (not reported as findings):**
  - The single storage thread (`app/resources.py` 61) may limit throughput under heavy cache traffic; measure
    with `helper/loadtest.py` before changing it.
  - NAT64 prefixes (`64:ff9b::/96`) are accepted by `is_global`. Whether the deployment network translates them to
    private IPv4 addresses was not checked.
- **By design, with a cost:**
  - Every browser job starts a fresh Chrome profile (about 1–3 s). This is the price of cross-request isolation.
  - On Colab's single browser slot it bounds JavaScript throughput to roughly 15–25 pages per minute.
