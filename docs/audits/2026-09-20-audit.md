# Audit of 20 September 2026 — release 0.8.0 (`1e4db5d`)

Full read of `app/` (36 modules, ~2800 lines) plus a live run against three sites.
Findings are numbered `B01`–`B24` to keep them apart from `A01`–`A25` of
[the audit of 17 September](2026-09-17-audit.md).

Every finding below was reproduced in this repository: either by tracing the code path
and naming the failing sequence, or by measurement against a running service. Findings
that a reviewer proposed but that the code does not support are not listed.

## Live test: three sites

Service started from this checkout on `127.0.0.1:8125` with an API key, the shipped
default user agent and one Uvicorn worker.

| Site | URL | Result |
|------|-----|--------|
| Serlo | `de.serlo.org/mathe/1573/vektor` | `success=true`, 200, trafilatura/ok, 3620 chars, 483 words, 45 links, 26 formulas, 2.8–3.5 s cold, 0 ms cached |
| LEIFIphysik | `leifiphysik.de/mechanik/…/geschwindigkeit` | `success=false`, **403**, `extraction_status=blocked`, "Just a moment…" |
| Wikipedia | `de.wikipedia.org/wiki/Photosynthese` | `success=true`, 200, trafilatura/ok, 163 566 chars, 13 147 words, 1110 links, 39 headings, 125 ms cached |

Observations:

- **Serlo** is server-rendered, so the HTTP path is enough; auto mode does not start a
  browser. Metadata, links and the article body are complete. Its formulas are wrong,
  see B02.
- **LEIFIphysik is behind a Cloudflare interstitial for every non-interactive client.**
  Tested: HTTP with the project user agent, HTTP with a current Chrome user agent, the
  article and the site root, `mode=js` with `accuracy` and with `speed`. All six answer
  403 "Just a moment…"; real headless Chrome gets the "Sicherheitsservice" block page
  after 48 s. `robots.txt` itself answers 200 for the same clients, so this is bot
  protection on HTML, not a robots rule. The service classifies it correctly
  (`extraction_status=blocked`, `success=false`) and — correctly — does not spend a
  browser start on a 4xx in auto mode.
- **Wikipedia** extracts cleanly, but all mathematics is silently dropped, see B03.
- Batch of all three: `total=3 succeeded=2 failed=1` in 1531 ms.
- `extract_links` and `extract_metadata` do not change a single byte of the extracted
  text (five variants, identical SHA-256) — the flags are side-effect free.

## High

### B01 — Worker teardown runs on the event loop

`app/workers.py:169`. `_stop(dead)` is called synchronously inside `async def run`,
unlike its two siblings at `:162` and `:183`, which both use `asyncio.to_thread`. The
chain is `_Slot.stop` → `_kill` → `subprocess.run(["taskkill", …, "/T", "/F"], timeout=5)`
→ `process.join(timeout=1)` → `TemporaryDirectory.cleanup()`, i.e. an `rmtree` of a
Chrome profile. All of it on the loop thread.

This is the routine error path: every worker-reported error (`:155`), every deadline and
every cancellation passes through it.

Measured against the running service, pinging `/health` every 20 ms while one browser job
fails:

| Case | Median gap between pings | Worst gap |
|------|--------------------------|-----------|
| fast crawl (baseline) | 22.1 ms | 29 ms |
| browser, certificate error | 22.5 ms | **385 ms** |
| browser, deadline while Chrome renders | 22.0 ms | **512 ms** |
| browser, deadline while Chrome renders (2) | 22.2 ms | **685 ms** |

During that window nothing else on the loop runs — including the `EgressProxy` relay
tasks that carry *all* Chrome traffic of every other in-flight browser job. The effect is
also visible to the client that caused it: a request with `timeout_ms=4000` returned
after 5981 ms.

The synchronous call is not an oversight one can simply `await` away: the handler runs
inside `except BaseException`, so an `await` would re-raise `CancelledError` and skip the
cleanup. A fix has to hand the work to a thread and keep a reference to it, so that
cancellation cannot drop it and `close()` can still wait for it.

### B02 — MathML without a TeX annotation is turned into wrong text

`app/markup.py:53-65`. When a `<math>` element carries no
`<annotation encoding="application/x-tex">` and no `data-tex`/`data-latex`, the code falls
back to `equation.get_text(" ", strip=True)` and wraps the result in `$$…$$`.

Serlo serves pure presentation MathML: 29 `<math>` elements on the Vektor article, zero
annotations, zero `data-tex`. The fallback flattens the tree, so `msqrt`, `msup` and
`mfrac` lose their meaning while the output still claims to be LaTeX:

| On the page | In the response |
|-------------|-----------------|
| \|a⃗\| = √(a₁² + a₂²) | `$$\| a → \| = a 1 2 + a 2 2$$` |
| a⃗ = (2, 3)ᵀ | `$$a → = ( 2 3 )$$` |

The square root is gone without a warning and the exponents have become adjacent digits.
A reader — or a model consuming the Markdown — cannot recover the formula, and the `$$`
fences assert a precision that is not there. 26 of 26 formulas on that page are affected.

### B03 — Wikipedia's formulas never reach the output

`app/markup.py:53-65` together with `app/html_converter.py:87-101`. Wikipedia *does* ship
`<annotation encoding="application/x-tex">`, and `prepare_html` substitutes it correctly —
verified on `de.wikipedia.org/wiki/Satz_des_Pythagoras`: 289 `<math>` elements in, 578
`$$` markers out. But those markers sit inside
`<span class="mwe-math-mathml-a11y" style="display: none;">`, and trafilatura drops hidden
content:

| Converter | Characters | Formulas in the output |
|-----------|-----------:|-----------------------:|
| `trafilatura` (default) | 69 790 | **0** |
| `markitdown` | 162 727 | 289 |
| `bs4` | 62 071 | 289 |

So with the shipped default every formula of a mathematics article is silently lost — not
degraded, absent. `a² + b² = c²` does not appear anywhere in the extraction of
"Satz des Pythagoras". The substitution has to leave the hidden a11y wrapper, otherwise it
only produces text that the next stage throws away.

## Medium

### B04 — The robots.txt cache is shared, but filled with caller-controlled transport

`app/robots.py:30-41`. The entry is keyed on the origin alone (`"robots:" + origin`), while
`_fetch` passes the requesting client's `options` — including `proxy` and
`allow_insecure_ssl` — to `fetch_http`. The result cache does the opposite and deliberately
hashes every option plus the network policy (`app/result_cache.py:12-19`).

Both directions are reachable:

- *Deny*: `{"respect_robots_txt": true, "proxy": "http://198.51.100.9:8080"}` with a proxy
  that refuses. The guard answers 502, `robots.py:45` caches `{"all": False}`, and for
  `RETRY_SECONDS` (300) **every** robots-respecting crawl of that origin gets 403.
- *Allow*: point `proxy` at a host you control, answer `User-agent: *` / `Allow: /`. That
  text is cached for `KEEP_SECONDS` (3600), so later honest requests bypass the site's
  real robots.txt.

The user agent is correctly *not* baked into the entry — only the raw text is cached and
re-parsed per request (`robots.py:36`).

### B05 — The full-page screenshot clamps height but not width

`app/js_fetcher.py:39-48`. `height` is capped at `SCREENSHOT_MAX_HEIGHT`, but
`"width": content["width"]` is taken straight from `Page.getLayoutMetrics().cssContentSize`,
which the page controls. A page with `body { width: 200000px }` requested with
`mode=js, screenshot=true, screenshot_full_page=true` asks Chrome for a 200000 × 20000
bitmap: a renderer out-of-memory on the shared browser worker, or a base64 string of
hundreds of megabytes that goes into `screenshot_base64` and then into the result cache.
`max_bytes` explicitly does not cover screenshots.

The width path is untested: `tests/test_browser.py:455-462` hardcodes `"width": 1280`.

### B06 — Worker startup also runs on the event loop

`app/workers.py:149`. `_Slot()` performs `_remove_leftover_directories()` (an `rmtree` per
leftover Chrome profile) and a `spawn`-context `Process.start()`, i.e. it launches and
primes a fresh interpreter — on the loop thread. Reached on the first job, on every job
after a kill, and on every `WORKER_MAX_JOBS` retirement. Measured: up to 59 ms, small next
to B01 but the same defect class and the same fix.

### B07 — `slot.exchange` and DNS share the default executor

`asyncio.to_thread` uses the loop's default executor (`min(32, cpu+4)` threads).
`app/workers.py:152` holds one of those threads for the *entire* job — up to
`DEFAULT_TIMEOUT_SECONDS` (120 s) — while `app/egress_proxy.py:136` queues one blocking
`socket.getaddrinfo` per proxied browser connection (`app/security.py:44`, no timeout, no
cache), up to `max_connections` per fetch. A page with many third-party hosts can fill the
executor queue, so a second request's `to_thread(slot.exchange, …)` waits there while
holding a capacity slot and a worker slot, burning its deadline before it reaches the
worker. `_stop` calls queue behind the same backlog.

### B08 — An unguarded `await` in `finally` can replace the result

`app/service.py:64-70` (and the same pattern at `:105`). `metrics.record(...)` runs in a
`finally` with no guard. `Metrics._record` uses `diskcache.transact()`, whose default is
`retry=False`, so it raises `diskcache.Timeout` when `BEGIN IMMEDIATE` cannot be taken —
the state store is shared across Uvicorn processes, and `.env` here sets
`UVICORN_WORKERS=2`. Because it is in `finally`, that exception *replaces* both the
successful `CrawlResponse` and the sanitized `CrawlError` with an unhandled 500.

Consequence in a batch: `asyncio.gather` at `:77` is called without
`return_exceptions=True` and `_batch_item` catches only `CrawlError`, so one escaping
exception completes the batch while its siblings keep running uncancelled — holding
capacity slots, browser workers and rate-limit reservations with their results discarded.

### B09 — Per-process gauges under shared metric names

`app/main.py:112-125`. Counters come from the shared store and aggregate correctly, but
`extraction_ready`, `extraction_active_requests`, `extraction_waiting_requests` and
`extraction_pool_workers` are read from whichever Uvicorn worker answers the scrape, with
no `pid` label. With `UVICORN_WORKERS=2` the series flaps between two processes and the
fleet's real active/busy count is never exposed. `/health` and `stats["capacity"]` have the
same property.

## Checked and found clean

- **SSRF.** Two stages: `resolve_target` on every redirect hop (`http_fetcher.py:98`) and
  again per connection inside the guard (`egress_proxy.py:136`), which dials the numeric
  address that was checked — DNS rebinding between check and connect cannot help. All
  A/AAAA answers must pass. Verified live: loopback, `localhost`, `169.254.169.254`,
  `[::1]`, `0177.0.0.1` and `2130706433` all answer 400 "Target blocked by network policy";
  `file://` and `ftp://` are rejected by the schema. Chrome cannot egress around the guard
  (`--proxy-server` plus `--proxy-bypass-list`, `--host-resolver-rules`, `--disable-quic`,
  WebRTC disabled), and neither `--disable-web-security` nor `--ignore-certificate-errors`
  is used.
- **Authentication.** `secrets.compare_digest` on bytes; `/crawl`, `/crawl/batch`, `/jobs`,
  `/jobs/{id}`, `/stats` and `/metrics` all answer 401 unauthenticated (verified live);
  `/docs`, `/redoc` and `/openapi.json` answer 404 while a key is set; a non-loopback bind
  without a key refuses to start. `admit()` runs after authentication, so unauthenticated
  traffic cannot drain the token bucket.
- **Body and decompression bounds.** 1.2 MB body → readable `413`; gzip/deflate are decoded
  with a bounded output allocation, unknown encodings rejected, wire bytes capped,
  redirects capped at 11 with loop detection, `Retry-After` clamped to 30 s, robots.txt at
  512 KiB.
- **Header injection.** `user_agent` and `accept_language` reject anything outside
  0x20–0x7E, `X-Request-ID` is reflected only on `[A-Za-z0-9._-]{1,64}`, and no filesystem
  path is built from user input (cache keys are SHA-256 hex).
- **Worker-slot accounting and pool close.** Exactly one `put_nowait` per successful
  `idle.get()`; a stopped slot is replaced by `None` before the `finally`; `closed = True`
  is set before the running snapshot, so no task can slip past it.
- **Coalescing.** No await between the in-flight check and the assignment, followers copy
  deeply, a follower's cancellation cannot kill the leader, and a waiting follower holds no
  capacity slot.
- **Shared state.** Metrics and rate buckets both write inside `store.transact()`
  (`BEGIN IMMEDIATE`), which serializes writers across Uvicorn processes.
- **Lock ordering.** Always batch semaphore → capacity semaphore → worker slot; no task
  holds two pool slots at once; every queue is bounded.
- **Log and error hygiene.** All `CrawlError` messages are fixed strings or a validated
  `net::ERR_…` code, worker failures report only the exception class name, loguru runs with
  `diagnose=False`, failure logs carry the host but never path or query, and ETag/
  Last-Modified are bound to their issuing URL so a redirect target cannot receive them.
